# Cache Friendly · 缓存友好（SillyTavern 插件）

让世界书和变量别把 prompt 缓存打碎，省钱。

## 它做什么

缓存只认"从开头起一模一样"的那一段。世界书里**会变的条目**放在角色卡前后时，每轮都会让后面整段聊天记录的缓存作废，等于每轮全价。

这个插件在酒馆挑世界书条目之前，把会变的条目改派到**聊天最末尾**（深度 0）：

- 绿灯条目（关键词触发，这轮亮下轮灭）
- 内容里带 `{{getvar}}` `{{random}}` `{{time}}` `{{roll}}` 这类宏的条目
- 内容里有 `<% %>` 模板的条目（变量/状态栏插件常用）
- （可选）按深度插入的条目，统一收到深度 0

**不会变的常驻条目原地不动**，作者怎么摆的就怎么摆。插件只改本轮的临时副本，**不会改你的世界书文件**，关掉就是原版。

实测：一张绿灯 + 随机宏的世界书，同一段对话里能被缓存复用的部分，从 2% 提到 82%。

## 缓存体检（1.3.0 新增）

插件面板里多了一行"缓存体检"：每轮发送前，把这一轮要发的内容跟上一轮比一比，显示**前面有百分之多少一模一样**——只有这一部分能吃到缓存。

掉到 70% 以下时会弹一个小提示，告诉你**从哪儿开始变的**，能认出来的会直接说是哪条世界书、角色卡的哪一栏、还是向量召回。

- 显示 80%～90% 以上：前面很稳，缓存该命中就会命中。如果用量记录里缓存还是 0，问题在接口那边，不在酒馆。
- 显示很低：照着提示去找那条在变的内容，挪到后面或者关掉。

只在本地比较，不发任何额外请求。不想看可以关掉。

## 向量召回挪到末尾（1.2.0 新增）

酒馆自带的向量召回（聊天记录向量化、资料库）每轮捞出来的片段都不一样，默认却插在主提示词里，也就是聊天记录前面。每轮一变，后面整段缓存就全废。

插件会在向量召回把内容准备好之后，把它挪到聊天最末尾（深度 0）。不改向量插件自己的设置，关掉开关就恢复原样。

实测（模拟每轮召回不同片段）：能复用的前缀从 **1%** 提到 **80%**。

## 安装

**最简单：在酒馆里直接装。** 打开「扩展」面板 → 点「安装扩展」→ 粘贴这个地址 → 安装：

```
https://github.com/kmiumiukaltine-maker/SillyTavern-CacheFriendly
```

装好后在扩展面板里找到 **Cache Friendly · 缓存友好**，默认就是开着的。

**手动装也行：**

1. 下载这个仓库（Code → Download ZIP），解压后把整个文件夹放进
   `SillyTavern/data/default-user/extensions/`
   （多用户的话把 `default-user` 换成你的用户名）
2. 重启或刷新酒馆。
3. 打开「扩展」面板，找到 **Cache Friendly · 缓存友好**，勾上开关（默认就是开的）。

## 自动开 Claude 缓存（1.1.0 新增）

用 **"自定义（OpenAI 兼容）"接口连 Claude 模型**（模型名里带 claude）时，勾上「自定义接口用 Claude 时自动开缓存」，插件会自己打缓存标记：system 段末尾一个，聊天记录里最后两条用户消息各一个，缓存跟着对话往前滚，**system 和聊天记录都能缓存**。不用改任何配置。

实测（Sonnet）：第 4 轮起每轮约九成输入走缓存。前提是你用的接口会把 `cache_control` 标记传下去；用量记录里看到"缓存读取 / cache read"就说明生效了。读取和写入都是 0，就是没传过去，改用下面"Claude"接口的办法。

## 用"Claude"接口的：开缓存本身

插件只负责"别把前缀弄乱"，缓存要在服务器上打开。编辑 `SillyTavern/config.yaml`，找到 `claude:` 那一段，改成：

```yaml
claude:
  enableSystemPromptCache: true
  cachingAtDepth: 0
  extendedTTL: false   # 聊得慢、经常隔十几分钟才回一句，就改成 true（1 小时缓存）
```

改完重启酒馆。

- 用 **"Claude"接口来源**：上面三行就够了。
- 用 **Gemini、OpenAI、DeepSeek** 等：它们大多自动按前缀缓存，不用开开关，插件让前缀稳定，它们自己就会命中。
- 用 **"自定义（OpenAI 兼容）"连 Claude 模型**：原版酒馆在这条路上不发缓存标记，靠插件的"自动开缓存"开关。

## 其他会打碎缓存的写法（插件管不到，自己注意）

- 预设、角色卡、主提示里（聊天记录**前面**的部分）写了 `{{random}}`、`{{time}}`、变量宏。
- 作者注释（Author's Note）插在中间深度：建议深度设成 0。
- 聊天记录超过上下文长度以后，酒馆每轮从最前面砍一条，前缀每轮都变。上下文开大一点、或者定期总结开新聊天，能缓解。
